Learn by building

AI Engineer Exercises

Thirteen small programs you finish yourself, from your first API call to an agent with memory. Every example comes from one place: kharif farming in Maharashtra. Written in TypeScript against the Claude API.

How to run it Study plan Source on GitHub

How to run it

You need two things: Node 20 or newer, and a Claude API key from console.anthropic.com. Nothing else is installed globally.

  1. Get the code

    git clone https://github.com/BaluRaut/ai-engineer-exercises.git
cd ai-engineer-exercises
npm install

    Check your Node version first with node --version. If it starts with 18 or lower, update it.

  2. Give it your key

    export ANTHROPIC_API_KEY=sk-ant-your-key-here

    On Windows PowerShell use $env:ANTHROPIC_API_KEY = "sk-ant-your-key-here". This lasts until you close the terminal. To keep it, copy .env.example to .env and put the key there, or add the export line to your shell profile. Never commit the key.

  3. See what is there

    npm run list

    Prints all thirteen exercise folders.

  4. Run the first one

    npm run ex -- 01

    The two dashes matter. They tell npm that 01 is for the script, not for npm itself.

The four commands you will use

CommandWhat it does
npm run listLists every exercise.
npm run ex -- 07Runs your version of exercise 07, with its checks.
npm run ex -- 07 --solutionRuns the finished version, so you can compare.
npm run typecheckChecks every file compiles. Makes no API calls and costs nothing.

A ✔ means that part works. A ✘ prints a hint telling you what is missing. Keep going until every line is a tick.

What each exercise folder holds

  • README.md — what you are building, the steps, and what finished looks like. Read this first, all of it.
  • exercise.ts — the scaffold. Find the TODO comments and fill them in. The checks at the bottom grade you.
  • solution.ts — one working answer. Open it after you have tried, not before.

The thirteen

Do them in order. Each one assumes the ones before it.

Part one

Talk to the model

  1. First call

    Send a message, read the text blocks that come back, watch the token count.

    API · model · token · inference

  2. System prompt

    Give the model a standing job, and watch the same question get a different answer.

    system prompt · prompt

  3. Conversation

    The API remembers nothing. A chat is a list you resend every single turn.

    context window · memory

  4. Structured output

    Get typed fields your code can use instead of prose you have to parse.

    structured output
Part two

Give it hands

  1. Streaming

    Show words as they are generated, and measure the wait you just removed.

    streaming · latency

  2. Tools

    Let the model call a function you wrote, so prices are real instead of invented.

    tool · hallucination

  3. Agent loop

    Write think, act, look, repeat by hand, so you know what the shortcuts hide.

    agent · agentic AI

  4. RAG

    Find the right pieces of your own notes first, then answer with citations.

    RAG · embedding · vector database
Part three

Make it hold up

  1. Prompt caching

    Stop paying full price for the same long instructions on every request.

    prompt caching

  2. Guardrails

    A scope check before answering, a scoped prompt, and handling a refusal.

    guardrails · alignment

  3. Evals

    Score a fixed question set so you know whether a change helped or hurt.

    evals · bias

  4. Multi-agent

    Split one job across three workers running at once, then merge their reports.

    multi-agent

  5. Memory

    Save facts after one conversation and load them into the next.

    memory

Study plan

Four weeks at about an hour a day. Faster is fine: two exercises a day finishes in a week. Slower is also fine: one a week finishes in three months and you will remember more. What matters is that you attempt before you read the solution, every single time.

Week 1

Talk to the model

By Sunday you can: send a request, set the model's job, hold a conversation, and get an answer as typed fields.

  1. Exercise 01. Then break it on purpose: set max_tokens to 20 and watch stop_reason turn into max_tokens.
  2. Exercise 02. Then write a system prompt for an app you want to build, and run the same question through both.
  3. Exercise 03. Then print the token count on every turn and watch it climb. That climb is your bill.
  4. Exercise 04. Then add a field the notes cannot support and see what the model puts in it.
  5. Catch up or rest. Re-run anything that felt shaky, without looking at the solution.

Checkpoint. From an empty file, write a script that asks one question under a system prompt and prints only the text. No copying. If you cannot, redo day two.

Week 2

Give it hands

By Sunday you can: stream an answer, let the model call your functions, run an agent loop, and ground answers in your own documents.

  1. Exercise 05. Compare the time to first word against the total time. That gap is why streaming exists.
  2. Exercise 06. Then add a second tool, a fake weather lookup, and ask a question that needs both.
  3. Exercise 07. The hardest one so far. Give it two sessions if you need to. Print every tool call as it happens.
  4. Exercise 07 again, from scratch, without the solution open. The loop is the centre of everything that follows.
  5. Exercise 08. Then ask something the notes do not cover and check that it says so instead of inventing.

Checkpoint. Explain out loud, to a person, the difference between a tool and retrieval. Both bring outside facts in. A tool is called by the model when it decides it needs one. Retrieval is fetched by your code before the model ever sees the question.

Week 3

Make it hold up

By Sunday you can: cut your bill, keep the app on task, measure whether a change helped, split work, and remember between sessions.

  1. Exercise 09. Watch the cache write on call one and the cache read on call two. Then change one character in the system prompt and watch the read go to zero.
  2. Exercise 10. Then try to talk the advisor off topic. Where it slips, tighten the classifier, not the big prompt.
  3. Exercise 11. Add five of your own questions to data/evals.json, including two you expect to fail.
  4. Exercise 12. Then time it against doing the three fields one after another.
  5. Exercise 13. Then decide what your app should never store about a person, and write that rule into the extraction prompt.

Checkpoint. Change the system prompt in exercise 11, run the evals again, and show the score moved. Making a change and proving it helped is the job, in one move.

Week 4

Build your own

No new exercises. Take an idea of your own and assemble it from the pieces you now know.

  1. Write the system prompt and the one hard limit. from 02
  2. Define the output shape your app actually needs as a schema. from 04
  3. Add one real tool that reads something true, not invented. from 06
  4. Put your own documents behind it and make answers cite them. from 08
  5. Cache the stable prefix, add a scope check, and write ten eval questions. from 09, 10, 11

Finished when your evals pass, the cost per answer is one you would pay, and you can hand it to someone who was not there when you built it.

How to work through one exercise

The order matters more than the speed. Every step you skip here shows up later as a gap.

  1. 5 min

    Read the whole README

    Including the part at the end about what to notice. It tells you why the exercise exists, not just what to type.

  2. 25 min

    Attempt the TODOs with the solution closed

    Being stuck is the part where learning happens. Sitting in it for ten minutes is normal and is not a sign you are bad at this.

  3. 2 min

    Run it and read the failures

    Each ✘ carries a hint. Fix one at a time and run again.

  4. 10 min

    Only now, open the solution

    Do not just check that it matches. Find the lines that differ from yours and work out why the author chose that.

  5. 3 min

    Write one sentence about what surprised you

    Keep these in one file. After thirteen exercises that file is worth more than the code.

You have actually learned it when

You can explain the idea to someone who has never written code, using an everyday comparison. If you cannot explain a context window as a page, a notepad, or a countertop, you know the word and not the thing. The AI Dictionary gives every term three such comparisons, in English and Marathi.

When something breaks

It says the API key is missing or invalid
Run echo $ANTHROPIC_API_KEY. Empty means the export did not survive, usually a new terminal tab. Export it again, or put it in .env.
Error 429, rate limited
You sent too much too fast. Wait a minute. In exercises 11 and 12, lower the concurrency number passed to mapLimit from 3 to 1.
Exercise 09 shows a cache read of zero
Either the prefix is shorter than the model's minimum cacheable size, so add more notes, or something inside it changed between the two calls. A timestamp or a random value in the system prompt will do it.
TypeScript is complaining before I even run
Good. Run npm run typecheck to see every problem at once. It calls no API and costs nothing. Most complaints are the compiler stopping you from reading .text off a block that might not be text.
I am worried about the cost
Each exercise is a handful of small calls. To spend less while learning, run on a cheaper model: CLAUDE_MODEL=claude-haiku-4-5 npm run ex -- 07. Set it once per terminal with export CLAUDE_MODEL=claude-haiku-4-5. Watch the token line printed after every call; noticing it is a habit worth building.
My answer differs from the solution but the checks pass
Then you are fine. The checks test behaviour, not wording. Models do not give identical answers twice, which is itself worth sitting with.
